# Данные

В проекте два датасета последовательных рекомендаций. Оба хранятся в одном формате и
запускаются одной командой `python main.py --data_name=<имя>`.

## Формат

| Файл | Содержимое |
|---|---|
| `data/<имя>.txt` | Строка на пользователя: `user item1 item2 …`, объекты в порядке времени. Пользователи нумеруются 1..N, объекты 1..max_item без пропусков (0 — паддинг) |
| `data/<имя>_sample.txt` | Строка на пользователя в том же порядке: `user neg1 … neg99` — 99 разных объектов не из истории пользователя |

Разбиение leave-one-out делает код модели: последний объект истории — тест, предпоследний —
валидация, остальное — обучение. При оценке правильный объект ранжируется среди своих 99 негативов
(HIT@K, NDCG@K, MRR). Флаг `--full_sort` включает ранжирование по всем объектам.

## Beauty

Amazon Beauty из репозитория авторов, лежит в `data/` готовым — вместе с файлом негативов и
обученной моделью `output/FMLPRec-Beauty-4eval.pt`.

## MovieLens-1M

Источник: https://grouplens.org/datasets/movielens/1m/ (оценки фильмов, 2000–2003).
Лицензия GroupLens не разрешает распространять данные, поэтому файлов ML-1M в репозитории нет:
каждый собирает их у себя командой

```bash
python scripts/get_ml1m.py
```

Скрипт скачивает архив, запускает `scripts/prepare_ml1m.py` и `scripts/gen_neg_samples.py` и проверяет
результат через `scripts/data_stats.py`. Результат детерминирован: MD5 файлов должны совпасть с
таблицей ниже. Если не совпали — напишите участнику 1.

Решения при подготовке (`scripts/prepare_ml1m.py`):

- все оценки (1–5) считаются взаимодействием, как в SASRec и FMLP-Rec;
- итеративный 5-core: пользователи и фильмы с < 5 взаимодействиями удаляются;
- история сортируется по `(timestamp, MovieID)`: 77 % оценок поставлены в ту же секунду, что и другая
  оценка того же пользователя (до 30 штук подряд), поэтому без второго ключа порядок был бы случайным;
- id фильмов перенумерованы в порядке первого появления, соответствие с исходными MovieID —
  в `data/ML-1M_item_map.csv`.

Контроль: число пользователей, фильмов и взаимодействий совпадает с версией ML-1M из репозитория
SASRec (Kang & McAuley, 2018) — 6 040 / 3 416 / 999 611.

Негативы (`scripts/gen_neg_samples.py`): 99 объектов на пользователя, равномерно из всех объектов,
без повторов и без объектов из истории, `seed = 42`. Так же устроен `Beauty_sample.txt` авторов.

## Статистика

| Датасет | Пользователи | Объекты | Взаимодействия | Ср. длина | Медиана | Мин | Макс | Плотность |
|---|---|---|---|---|---|---|---|---|
| Beauty | 22 363 | 12 101 | 198 502 | 8.9 | 6 | 5 | 204 | 0.07% |
| ML-1M | 6 040 | 3 416 | 999 611 | 165.5 | 96 | 18 | 2 277 | 4.84% |

Датасеты сильно различаются: Beauty — короткие истории и очень разреженные данные, ML-1M — длинные
истории (медиана 96) и плотные данные. При `max_seq_length = 50` (значение по умолчанию) модель на
ML-1M видит только последние 50 объектов истории.

| Файл | MD5 |
|---|---|
| Beauty.txt | `cb03635343187f36526ed4ba48102b53` |
| Beauty_sample.txt | `7e17a81b6d818df8ea4b8b706688cd1c` |
| ML-1M.txt | `399678dd231845c14534294997da452a` |
| ML-1M_sample.txt | `bf63ced361f5960de760b56b69de4e2b` |

Пересчитать: `python scripts/data_stats.py Beauty ML-1M`.

## Новые датасеты

Любой файл `data/<имя>.txt` в этом формате подключается автоматически, вписывать его в `utils.py`
не нужно. Негативы к нему: `python scripts/gen_neg_samples.py --data_name <имя>`, проверка:
`python scripts/data_stats.py <имя>`.
